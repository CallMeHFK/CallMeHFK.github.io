01 — Seams

四个接缝

四处机制不同，位置相同：都在 agent 与外部系统之间，数据与控制由此进出。

每个位置设一道判断，实现方式一致：先定确定性规则，规则覆盖不到的部分再交由模型；判定不确定时默认拦截。

F1

工具接缝

触发于工具调用前后

工具调用的前与后各设一道检查：执行偏离目标时注入纠正（过程监督）；交付物写入错误位置时拦截，并返回应接收的执行者（输出路由）。

5 个公开仓库
F2

记忆接缝

触发于上下文写入与检索

长期记忆需可检索、可排序、可复现，不以持续扩张上下文替代；结构层不依赖模型输出。

3 个公开仓库
F3

网络接缝

触发于出站连接

出站流量绑定指定网卡，数据去向可判定；判定失败时关闭连接，不做放行降级。

2 个公开仓库
F4

会话接缝

触发于多 agent 会话

多个 agent 处于同一会话，可被点名、可并行应答；会话进程可运行在端侧，不必集中到单一客户端。

04 — Systems

系统设计

以下三个系统均从零实现并已开源。未开源项目不在本节范围内。

内容取自公开仓库 README，版本截至 2026-10-22。

S1 / 工具接缝 · 过程监督

agent-shepherd ↗

  1. 两层检测：确定性规则覆盖循环、回退、越权编辑等常见偏离；模型判定仅在规则无法覆盖时启用。
  2. 阈值由测量确定；配套评测命令可注入单点故障，输出精确率、召回率与延迟。
  3. 纠偏结果回流至规则库，多次被否定的条目自动停用。

v0.4.0 · MIT · 公开仓库

S2 / 工具接缝 · 输出路由

dispatch-guard ↗

  1. 将派发约束从系统提示词下移到工具调用入口，拦截不应由当前 agent 产生的交付物。
  2. 路由表支持热加载，并自检冲突与不可达规则；无配置时生成只告警的草稿，确认后生效。
  3. 语义仲裁层为可选组件，默认关闭，仅处理确定性规则无法判定的两类情形。

v0.1.11 · MIT · 公开仓库

S3 / 会话接缝 · 多 agent

agent-chatroom ↗

  1. 用户与多个 CLI agent 处于同一会话，支持点名、并行应答与流式输出。
  2. 回复路由由策略层决定：@ 精确点名，无 @ 时全员接力，并限制接力深度以避免循环触发。
  3. 不同来源的 agent 无需统一协议即可接入；中断按一等操作处理。

未发版 · 公开仓库

06 — Principles

运行原则

六条固定检查项，在开始任务前逐条确认。

改进以同一口径下的基线对比为准。工作原则 00
00先盘点，再行动建立基线 → 改进 → 与基线对比；未建基线不启动
01数据驱动不迷信源码 > 配置 > 运行态；数值一律由工具计算后引用
02逐字保真源数据不作修改；可加标注，不得以「优化」为由改写
03物理极限即边界参数调优可迭代；触及物理上限即转向，不做无效投入
04诚实纠错新数据推翻旧结论时，显式记录推翻关系与原因
05工具链即基础设施按任务安装，不长期膨胀；无回退方案不引入

检查项按序号执行，无优先级差别。
