SEC.01

$做什么

QwenPaw 插件。submit_to_agent 返回 task_id 之后，结果躺在子任务记录里，等某个 agent 主动去 check_agent_task。这个插件为每个任务注册一个 watcher，任务到达终态时把结果作为新的一轮回投到注册它的会话，父 agent 不需要轮询。

SEC.02

$快速开始

~/install.sh
SEC.03

$架构

parent ──► submit_to_agent ──► task_id
   │                              │
   │  以前：反复 check_agent_task ……忘了就永远不知道
   ▼                              ▼
watch_agent_task ──► watcher ──► 终态 ⇒ 结果回投父会话
SEC.04

$要点

F01
👀

watch_agent_task

注册即忘：watcher 盯住任务终态，结果作为新 turn 回投注册它的会话。

F02
💾

跨重启持久化

状态写在 ~/.qwenpaw/agent-task-callback.json，应用重启任务不丢。

F03
🪶

成本透明

每个被盯任务一个守护线程，20 秒一次 GET。

F04
🎛️

完整控制面

watch / callback_task_status / cancel_task_callback 三工具。

F05
🧩

即插即用

release zip 恰好携带运行时加载的三个文件。

F06
🚧

做不到就拒绝

ACP 通道（T3 Code 等外部 IDE 客户端）的 workspace 建在 WorkspaceRegistry 之外，回投的 console API 路由不回去。这类会话中 watch_agent_task 拒绝注册，并提示改用 check_agent_task 轮询。

SEC.05

$版本与限制

  • 已落地 v0.1.5

    安装路径理顺：插件 zip 上传 / URL 均可，运行中的 app 热加载并跑启动钩子，免重启

  • 限制

    ACP 会话（T3 Code 等外部 IDE 客户端）不可用：服务端直接构建工作区、绕过 WorkspaceRegistry，工具不注入。这是通道属性，不是缺陷。
