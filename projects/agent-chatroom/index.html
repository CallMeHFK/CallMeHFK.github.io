SEC.01

$为什么存在

用户与多个 CLI agent（qoder / claude / codex / codebuddy / grok / qwenpaw / 远程 pi …）在同一聊天室互聊：用户 @ 某个 agent 提问，agent 回复中再 @ 其他 agent 就能互相唤起；Web UI 实时流式展示回复与思考过程。三种接入方式并存——ACP 常驻会话（流式）、本地一次性 CLI、远程 SSH——所以「已装在本机的各家 agent」不需要先被改造成同一个协议才能进屋。

服务端是零框架的 node:http 加 SSE，前端是单页静态文件、零构建。SSE 事件对齐 AG-UI 分类法（TEXT_MESSAGE_* / THINKING_* / CUSTOM / STATE_*），字段名本身就是前后端契约——这条写在 PLAN.md 的 T8–T12 标题里：「前端契约已定，字段不得更改」。

SEC.02

$能力清单

F01
🗣️

回复路由是策略层，不在 prompt 里

@ 精确点名；无 @ 时全员接力；replyTo 链深 ≤ 3 防止无限对轰；发言冷却防抢话。谁该接这句话由代码判定，不指望模型自觉。

F02
⚡

并行应答（默认开）

同一轮被点名的多个 agent 同时发言，流式事件天然交错。parallel: false 可回串行旧路径。代价写在已知限制里：并行下回复入库顺序取决于各 agent 完成先后。

F03
🔌

三种 driver

src/drivers/ 下 acp / cli / ssh / abort 四类。ACP driver 走 @agentclientprotocol/sdk；cli 是一次性 stdin/stdout（stdin 必须关掉防挂起）；ssh 把命令送到远程 pi。abort 是一等公民：Driver.send 第三个参数就是 AbortSignal。

F04
🔇

一键停止 / 恢复

POST /api/rooms/:id/stop 中止全部进行中的回复并进入全员静音——静音期 postUserMessage 只记录不触发应答，且只发一次系统消息。acp driver 在 abort 时发 session/cancel 通知，cli / ssh 直接杀进程组。/resume 恢复并广播。

F05
❓

提问通道

agent 回复中输出独立一行 ASK: 主题 | 问题 即挂起等待用户答复（可配钉钉 webhook 通知），答复经 POST /api/rooms/:id/questions/:qid/answer 回流给该 agent 并走正常 send 流程。questionTimeoutSec 默认 600 秒，到期置 timeout。前提是 agent 肯遵守 ASK 约定——不输出就不挂起。

F06
🖼️

共享画布（插件）

agent 回复中输出 ```canvas 块（OpenUI Lang，依赖 @openuidev/lang-core）即生成图表 widget；全房间共用一份画布，用户只读。插件约定见 docs/PLUGINS.md，插件体系另有 voice 与 ui-proposal 两个，支持全局开关加房间级覆盖。

F07
🚪

多聊天室

RoomManager 管理多个房间并用 rooms.json 持久化，默认房间 lobby。每个房间独立参与者、独立画布（canvas-<roomId>.json）与独立事件流 /api/rooms/:id/stream。

F08
🔐

访问认证（可选）

口令不存明文，存域分隔 HMAC 摘要；会话 cookie 是 <expiryMs>.<sig>，HttpOnly; SameSite=Lax，默认 12h。同 IP 连续 5 次失败锁 60 秒（失败计数表有界：最多 1000 条、只留最近 5 分钟活跃）；口令与签名比较都走 timingSafeEqual，长度不泄露信息。启用后所有 /api/* 未带有效会话一律 401，SSE 流同样受保护。

F09
🧮

上下文预算

按房间可配 token 预算（默认 6000，估算口径 chars/3），超预算自动截断并保留主题锚点——截断不是砍尾巴，是保住这轮在聊什么。

F10
⚙️

运行时管理

/api/agent-configs 增删运行时 agent 配置（agents.yaml 只读保护），/api/plugins 切插件全局开关加房间级覆盖。agent 能力探测（model / thinkingMode / permissionMode）自动填下拉，force 重探复用 in-flight 去重。

F11
🧪

299 项测试，实跑全绿

npm test = tsx --test test/*.test.ts，20 个测试文件。本页写作时实跑一次：tests 299 · pass 299 · fail 0，2.25 秒。测试注入假时钟与临时目录数据文件，不真 sleep、不写项目根——所以它能在 CI 之外的任何机器上重复。

F12
📋

外部评审台账

docs/ISSUES.md 是一份编号到 #43 的评审台账（qoder + 人工核实），状态分 open / fixed / deferred / wontfix。当前 37 行里 25 fixed · 3 deferred · 9 open，open 的那 9 条连「本轮不修」的理由和剩余 scope 都写在表里。wontfix 一节专门用来记录误报，防止下次复查重提。

  • 边界

    链深 3 层封顶；并行下入库顺序取决于完成先后；thought 不入库（只经 SSE 实时广播，不写历史、不进后续上下文）；ACP 权限请求一律取消——driver 对 requestPermission 自动拒绝，所以 agent 无法执行需授权的写操作；页面门禁只覆盖 /、/index.html 与全部 /api/*，静态资源不设防，别把敏感信息放进去

    仓库没有 LICENSE 文件，也没有 CI 工作流；package.json 写着 0.1.0 但从未打 tag 或发 release。README 文末的「分支状态」表已落后于仓库：它标为未合并的 feat/auth-gate、feat/mobile-responsive、feat/agent-capabilities、feat/design-refresh 四个分支在远端都已不存在（合并后删除），HEAD 是 PR #48 的合并提交
