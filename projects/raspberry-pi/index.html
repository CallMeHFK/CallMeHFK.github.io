SEC.01

$做什么

个人树莓派与家庭服务器实验仓，活跃开发在 voicekit/：浏览器和语音助手开一场实时语音通话，你说中文，助手听懂、回答、用语音说回来。LLM 后端是跑在派上的 pi / sol-pi CLI agent，经 ssh 走 ACP 协议，所以助手能真的在派上执行工具。语音链路基于 LiveKit，信令走 HTTPS/WSS，媒体走 WebRTC UDP。

SEC.04

$要点

F01
🎙️

四段链路可换后端

VAD 用 livekit 内置 silero。STT 走 SiliconFlow ASR。LLM 是 GatewayLLM 回退链，顺序由 VOICEKIT_LLM_BACKENDS 配置。TTS 是 MiMo，SSE 流式返回 pcm16 / 24 kHz。

F02
🔗

工具能力来自派上

GatewayLLM 本身不支持工具调用，tools 参数会被忽略。工具能力来自 pi-acp 那一侧的 agent。

F03
🪜

桥有降级链

pi-acp（ssh ACP 常驻会话，流式加工具）失败时降到 pi -p（ssh 一次性，按句切块），再失败报错。桥只绑 127.0.0.1:8790。

F04
🚪

端口规则明确

8445 TCP 是唯一对外入口，7882 UDP 走媒体。7880 与 7881 未鉴权且因 --network host 绑在所有网卡上，README 要求不对外开。

F05
⏱️

冷启动超时已覆盖

ACP_INIT_TIMEOUT_MS 代码默认 12000，pi-acp 冷启动常超过 12 秒，部署值在 service 文件里覆盖为 30000。

F06
📓

评审台账有归宿

docs/issues/ 有 19 条编号发现，每条带 Severity、Evidence（file:line）与 Proposed fix。18 条已修并合入 main，1 条记为接受残余风险。

SEC.05

$版本与限制

  • 已落地

    voicekit 全链路：网关、LiveKit、worker、桥。流式 TTS 与 ASR。完整迁移到 Pi。

  • 已落地

    两轮评审的 19 条发现中 18 条已修：桥的 capture 上限与泄漏、reaper、send-mutex、ssh env，网关 ws pump，worker backend lock，livekit keys。

  • 限制

    没有自动化测试。test_plugins.py 是手工离线联调脚本，e2e.py 与 e2e_tailnet.py 需要 docker LiveKit、可 ssh 的 Pi 和付费 key 才能运行。

  • 限制

    仓库没有 LICENSE、CI 和版本。根 README 列出的子项目中只有 voicekit 在仓库里，agent-chatroom 已是独立仓库。不传 --keys 时 --dev 会退回占位符密钥，README 把这列为本项目最重要的一条安全约束。
