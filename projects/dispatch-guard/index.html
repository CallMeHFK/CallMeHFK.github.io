SEC.01

$为什么存在

多 agent 宿主里总会长出一个挂着几十个技能、还带着 spawn_subagent 的「全能」默认 agent——自己动手永远看起来最便宜，于是提示词里的派单规则输给工具列表。dispatch-guard 把执行从提示词搬到工具缝：即使模型决定自己写，写入也永远不会落盘，拒绝消息会精确告诉它该派给哪个 agent。

SEC.02

$能力清单

F01
⛔

工具缝拦截

write 调用被中间件拦下：交付物形状 且 环境中存在归属专家 agent → 拒绝写入并返回派单提示。无归属者不拦。

F02
🛡️

spawn 兜底

spawn_subagent 一并拒绝，作为配置层禁用的最后保险——绕路也被堵死。

F03
🔍

自动发现

插件自己扫描环境中的 agent，按声明技能起草派单表，然后才开始执法。

F04
📦

零依赖

纯 stdlib 实现，无 pip 依赖、无遥测。读操作、笔记、脚本、配置写入一律放行。

F05
🔐

路由表归你

仓库只发布脱敏的 routes.example.json，打包步骤拒绝把真实 routes.json 打进归档。

F06
🌱

unconfigured 模式

新装实例以挂载但不阻塞的模式上线，引导 agent 与你一起把派单表建起来。
