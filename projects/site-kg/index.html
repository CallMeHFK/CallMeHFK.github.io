SEC.01

$为什么存在

给它一个网站 URL，或者一个本地文档/代码目录，它抓取语料、构建知识图谱，并通过 MCP 的 9 个工具提供给 AI agent。结构层完全不需要 LLM：搜索、正文、图遍历全部免密钥工作。边只来自语料本身——没有交叉引用的站点会诚实返回 NOT-READY，而不是画一个装饰性的毛线团。

SEC.02

$能力清单

F01
🧭

两条进料

网页侧先探清单：Sphinx 站走 objects.inv 权威清单，Doxygen 走 navtree，再退 sitemap.xml 与同站 BFS。本地侧 ingest_local 吃 7 类文档、37 类代码扩展，外加 18 种无扩展名的构建文件（Makefile、Kconfig、COPYING……），边来自 markdown 链接、[[wikilink]] 与 import/include。

F02
🕸️

边只来自语料

从不臆造链接；无交叉引用就明说 NOT-READY。

F03
🔓

结构层零 LLM

search / get_page / neighbors / site_stats / list_sites 五个工具免密钥即可跑。

F04
💬

带引用的问答

ask：候选是关键词与 embedding 两路的并集，而不是关键词空了才问 embedding——关键词命中可能自信地错，正确页正躺在向量空间中段。图邻域扩上下文，embedding 重排后出答案，附来源页。

F05
🧩

可选语义层

配 SITE_KG_LLM_BASE 与 SITE_KG_LLM_KEY 才启用；cognee 做实体关系抽取。

F06
🧊

3D 图谱查看器

render_site 产出内联 Three.js 的单文件 HTML，人眼检查路径；AI 侧仍走 search / ask。

F07
🤝

车轮而非重造

MCP 用官方 SDK，JS 重站可选 Crawl4AI，只有胶水是自己的。

F08
🐢

礼貌爬取

遵守 robots.txt，限速抓取，httpx + bs4 + html2text。

F09
🪨

读一页不该扫全站

正文按 1–256 个哈希分片落盘，规模随语料长度自适应，get_page 只解一个分片：7.5 万文档的内核站从 8.3 秒降到冷启动约 12 毫秒。写入是临时文件加原子替换，meta.json 最后提交。收例统计把跳过拆成噪声目录 / 未知扩展 / OS 错误三类并附路径样本——覆盖率审计要能归因每一次跳过。
