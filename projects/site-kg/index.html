SEC.01

$为什么存在

给它一个网站 URL，或者一个本地文档/代码目录，它抓取语料、构建知识图谱，并通过 MCP 的 9 个工具提供给 AI agent。结构层完全不需要 LLM：搜索、正文、图遍历全部免密钥工作。边只来自语料本身——没有交叉引用的站点会诚实返回 NOT-READY，而不是画一个装饰性的毛线团。

SEC.02

$能力清单

F01
🧭

两条进料

网页侧先探清单：Sphinx 站走 objects.inv 权威清单，Doxygen 走 navtree，再退 sitemap.xml 与同站 BFS。本地侧 ingest_local 吃 7 类文档、37 类代码扩展，外加 18 种无扩展名的构建文件（Makefile、Kconfig、COPYING……），边来自 markdown 链接、[[wikilink]] 与 import/include。

F02
🕸️

边只来自语料

从不臆造链接；无交叉引用就明说 NOT-READY。

F03
🔓

结构层零 LLM

10 个工具里只有 ask 需要 LLM 配置，其余 9 个免密钥即可跑：两条进料、list_sites / site_stats、search / get_page / neighbors，以及两个查看器。

F04
💬

带引用的问答

ask：候选是关键词与 embedding 两路的并集，而不是关键词空了才问 embedding——关键词命中可能自信地错，正确页正躺在向量空间中段。图邻域扩上下文，embedding 重排后出答案，附来源页。

F05
🧩

可选语义层

配 SITE_KG_LLM_BASE 与 SITE_KG_LLM_KEY 才启用；cognee 做实体关系抽取。

F06
🧊

两个查看器，各管一件事

render_site 产出内联 Three.js 的单文件离线 HTML——按度数发光的节点、悬停提示、点击聚焦邻域、章节聚合视图（点球隔离）、即时检索、实时状态条（节点 / 边 / view% / FPS）。render_build 是 WebGPU 构建回放：图谱当场长出来，节点按语料顺序落到 3D 章节壳上，先证据边（ref / imports / contains），再每个派生关系维度一波飞行边，HUD 实时计数。0.25×–16× 变速，可重放 / 暂停 / 跳过。人眼检查走这两个，AI 侧仍走 search / ask。

F07
📡

边爬边长的实时会话

site-kg live 是地址优先的实时会话：先给地址，浏览器再问要建哪个场景。服务端爬取与增量布局的同时用 SSE 推给前端——节点按语料顺序抵达，边随页面解析绑定，派生关系维度默认隐藏且从不参与布局弹簧，因此不会扭构图。三个场景：Planets（章节即绕轨行星）、Neural（密集突触场）、City（一页一楼，楼层随该页 rank，亮着的窗是它发出的链接）。派生维度不参与布局这条，是「好看」不许压过「读得对」的写法。

F08
🎚️

预算与回退链

标签最多 40 个章节 / 12 个刻度，场景是合并后的 point/line 批次——没有逐节点对象，也没有 DOM 标签。实时场景优先 WebGPU（手写 WGSL；同一套布局、诞生、拖拽与终态状态同时喂两个后端，所以两者不会漂移），无 navigator.gpu 或拿不到 adapter 就在同一 canvas 上退 WebGL2，再没有就退到上限 5,000 节点的 canvas-2D 视图并指向离线归档取全图；WebGL 上下文丢失就地恢复。归档查看器是单个离线 HTML（默认内嵌二进制载荷，--external-data 才写 sk-*.bin），重放同样的场景。

F09
🤝

车轮而非重造

MCP 用官方 SDK，JS 重站可选 Crawl4AI，只有胶水是自己的。

F10
🐢

礼貌爬取

遵守 robots.txt，限速抓取，httpx + bs4 + html2text。

F11
🪨

读一页不该扫全站

正文按 1–256 个哈希分片落盘，规模随语料长度自适应，get_page 只解一个分片：7.5 万文档的内核站从 8.3 秒降到冷启动约 12 毫秒。写入是临时文件加原子替换，meta.json 最后提交。收例统计把跳过拆成噪声目录 / 未知扩展 / OS 错误三类并附路径样本——覆盖率审计要能归因每一次跳过。
