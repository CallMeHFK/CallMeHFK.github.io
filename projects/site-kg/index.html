SEC.01

$做什么

给它一个网站 URL 或一个本地文档/代码目录，site-kg 抓取语料、按语料里的链接建图，再通过 MCP 的 10 个工具提供给 agent。结构层不需要 LLM：进料、检索、正文、图遍历都免密钥。语料没有交叉引用时返回 NOT-READY，不生成推测出来的边。

SEC.04

$要点

F01
🧭

两条进料

ingest_url 爬站，ingest_local 收本地目录。网页侧先探清单：Sphinx 走 objects.inv，Doxygen 走 navtree，再退 sitemap 与同站 BFS。本地侧识别 7 类文档、37 类代码扩展和 18 种无扩展名构建文件。

F02
🕸️

边只来自语料

边由 markdown 链接、[[wikilink]] 与 import/include 产生，不做推测。没有交叉引用的站点返回 NOT-READY。

F03
🔓

结构层免密钥

10 个工具中只有 ask 需要 LLM 配置，其余 9 个直接可用。

F04
💬

带引用的问答

ask 的候选取关键词检索与 embedding 检索的并集，用图邻域扩展上下文，重排后返回带来源页的答案。

F05
🪨

正文分片

正文按 1 到 256 个哈希分片落盘，get_page 只解一个分片。7.5 万文档的站点从 8.3 秒降到冷启动约 12 毫秒。

F06
🧊

三个查看面

render_site 产出离线单文件 Three.js 查看器；render_build 用 WebGPU 回放建图过程；live 模式经 SSE 边爬边渲染，含 Planets、Neural、City 三个场景。

SEC.05

$版本与限制

  • 已落地

    mentions_symbol 提供跨文件符号边；render_site 与 render_build 覆盖离线查看与构建回放。

  • 计划

    可选语义层：配置 SITE_KG_LLM_KEY 后用 cognee cognify 在结构边旁生成实体/关系边。

  • 计划

    Crawl4AI 深爬，覆盖 Playwright 兜底也拿不下的 JS 站点。

  • 限制

    ask 与语义层依赖外部 LLM 配置，未配置时只有结构层可用。爬取遵守 robots.txt 与限速。
