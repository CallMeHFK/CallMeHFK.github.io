SEC.01

$为什么存在

「三思而后行」写在提示词里，而提示词会衰减——规则堆得越多，模型越学会略读。mu 的答案是把判断从提示词搬到工具缝，并且做得小而可测量：每个决策点只问一个有界问题，答案带着概率。jev-kernel 把它移植进 QwenPaw：tool.risk 问「这个调用会不可逆地破坏数据吗」，tool.approval 问「该等人类拍板吗」。不确定的问题级联给下一层裁判，一切落进账本。

SEC.02

$能力清单

F01
⚖️

有界类型化问题

每个决策点只问一题：noul（是/否带 P(yes)）、choice（选项带概率）、score（按标准打分）。

F02
🌊

裁判级联

拿不准的问题逐级上抛——后面的裁判只看到前面留下的不确定性。

F03
📒

判断账本

每个判决都进 ledger，事后可读、可审计、可复盘。

F04
🌫️

shadow 先行

shadow 模式只记录不干预——先读账本，确认靠谱再切 active。

F05
🔌

四种裁判传输

typesafe / http / llm / systemone，外加内置 jev / session 层。

F06
📦

零依赖

纯 stdlib，无 pip 依赖、无遥测；默认全惰性，不配裁判就不发任何请求。
