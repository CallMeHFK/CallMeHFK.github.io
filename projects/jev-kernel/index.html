SEC.01

$为什么存在

「三思而后行」写在提示词里，而提示词会衰减——规则堆得越多，模型越学会略读。mu 的答案是把判断从提示词搬到工具缝，并且做得小而可测量：每个决策点只问一个有界问题，答案带着概率。jev-kernel 把它移植进 QwenPaw：tool.risk 问「这个调用会不可逆地破坏数据吗」，tool.approval 问「该等人类拍板吗」。不确定的问题级联给下一层裁判，一切落进账本。同一套内核也跑在 ZCode · Qoder · Claude Code · Codex 的 PreToolUse 钩子上——四个宿主共用一份判决方言，安装脚本只往宿主的钩子配置里合并一条，保留既有钩子并先备份。

SEC.02

$能力清单

F01
⚖️

有界类型化问题

每个决策点只问一题：noul（是/否带 P(yes)）、choice（选项带概率）、score（按标准打分）。

F02
🌊

裁判级联

拿不准的问题逐级上抛——后面的裁判只看到前面留下的不确定性。

F03
📒

判断账本与 shadow 先行

每个判决都进 ledger，事后可读、可审计、可复盘；shadow 模式只记录不干预——先读账本，确认靠谱再切 active。

F04
🔌

四种裁判传输

typesafe / http / llm / systemone，外加内置 jev / session 层。

F05
📦

零依赖

纯 stdlib，无 pip 依赖、无遥测；默认全惰性，不配裁判就不发任何请求。隐私边界说清楚：被判断的调用内容本来就要发给配置的裁判，recordState 只管要不要往账本里再存一份。

F06
🫱

内核不许掐断 agent

裁判挂了、配置写坏了、账本写不进去——一律 fail open，绝不因为判断层死了就把工具调用永久挡住。坏配置读不进就退回默认值，enabled 是一个总开关：关掉之后判定层与依赖它的上层插件一起停，逐字节回到没有内核的行为。
