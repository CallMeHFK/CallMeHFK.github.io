SEC.01

$做什么

mu 式判断内核的 QwenPaw 移植。每个决策点只问一个有界问题，答案带概率：tool.risk 问这个调用是否会不可逆地破坏数据，tool.approval 问是否该等人类确认。不确定的问题级联给下一层裁判，所有判决落进账本。同一套内核也以 PreToolUse 钩子跑在 ZCode、Qoder、Claude Code、Codex 上，四个宿主共用一份判决方言。

SEC.04

$要点

F01
⚖️

有界类型化问题

每个决策点只问一题：noul（是/否带 P(yes)）、choice（选项带概率）、score（按标准打分）。

F02
🌊

裁判级联

拿不准的问题逐级上抛，后面的裁判只看到前面留下的不确定性。

F03
📒

判断账本与 shadow 先行

每个判决都进 ledger，事后可读可审计。shadow 模式只记录不干预，确认判决可靠后再切 active。

F04
🔌

四种裁判传输

typesafe / http / llm / systemone，外加内置 jev / session 层。

F05
📦

零依赖

纯标准库，无 pip 依赖、无遥测。默认全惰性，不配置裁判就不发请求。被判断的调用内容会发给配置的裁判，recordState 只决定是否另存一份到账本。

F06
🫱

fail open

裁判不可用、配置损坏、账本写入失败时一律 fail open，判断层不会永久挡住工具调用。坏配置读不进就退回默认值。enabled 是总开关，关闭后判定层与依赖它的上层插件一起停。
